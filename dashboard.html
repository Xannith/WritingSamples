Pipeline GUI

Streamlit Web App

A local Streamlit browser interface that wraps the full Document Review Pipeline. Upload a .md, .txt, .html, or .htm file, choose dry-run or live mode, click Run, and review the results from all four agents in one place — with one-click downloads for every output file.

Repo location

agents/pipeline-gui/app.py
Requirements: agents/pipeline-gui/requirements.txt

Runtime type

Streamlit web app
Runs locally in your browser
Default: http://localhost:8501

Dependencies

streamlit (from pipeline-gui/requirements.txt)
Plus: anthropic, python-dotenv from the classifier requirements

Required env variables

ANTHROPIC_API_KEY — required for live runs
Not required for dry-run mode

Launch command
PowerShell — from repo root 
# Install dependencies (first time)
pip install -r agents/pipeline-gui/requirements.txt
pip install -r agents/content-type-classifier/requirements.txt

# Launch the GUI
streamlit run agents/pipeline-gui/app.py

# Then open in browser:
http://localhost:8501
User flow

1. Upload a .md, .txt, .html, or .htm file
2. Choose dry-run (no API, for testing) or live run (calls Claude)
3. Optionally pick a model and name the output folder
4. Click ▶ Run Pipeline
5. Review agent status, final summary, and merged report
6. Download individual files or a ZIP of all outputs

CLI Coordinator

Python CLI

  --output agents/pipeline-runner/outputs/dry-run-test \
  --dry-run

Agents & Tools · Agent #1

Content Type Classifier

Python CLI

Classifies document content chunk-by-chunk by information type. Foundational to stateless content architecture: content cannot be modularized, governed, or reused intelligently until you know what kind of content each piece is. Supports 10 types: Policy, Process, Procedure, Reference, Learning, Definition, Governance, Image, Code, Video.

Repo location

agents/content-type-classifier/src/classify.py

Dependencies

pip install -r agents/content-type-classifier/requirements.txt
Includes: anthropic, python-dotenv

Required env variables

ANTHROPIC_API_KEY
Use --dry-run to skip the API call

Supported input formats

.md — split on headings
.txt — split on double newlines
.html / .htm — strip tags, then split

Launch command
PowerShell — from repo root 
python agents/content-type-classifier/src/classify.py \
  --input  agents/content-type-classifier/examples/sample-policy.md \
  --output agents/content-type-classifier/outputs/policy-report

# Dry run
python agents/content-type-classifier/src/classify.py \
  --input  examples/sample-policy.md \
  --output outputs/test --dry-run

# Use a different model
python agents/content-type-classifier/src/classify.py \
  --input  examples/sample-sop.md \
  --output outputs/sop-opus \
  --model  claude-opus-4-7

Agents & Tools · Agent #2

Crawl/Walk/Run Assessor

Python CLI

Evaluates each content chunk and assigns a readiness tier. Crawl (0.00–0.33): introductory content, anyone new to the topic. Walk (0.34–0.66): guided content, users with basic context. Run (0.67–1.00): expert-level content for experienced users and systems. Runs after the Content Type Classifier (Agent #1).

Agents & Tools · Agent #3

Content Gap Scout

Python CLI

Identifies missing information, structural weaknesses, unclear ownership, and other gaps that make content harder for humans or AI systems to use correctly. Exposes epistemic debt — the gap between what the content says and what it needs to say to be useful, reusable, and AI-ready. Gap severity: Critical, High, Medium, Low (20 gap types). Runs after Agents #1 and #2.

Accepts prior agent outputs as context for richer gap analysis.

Agents & Tools · Prompt Tool

Prompt Builder

Browser Tool

A three-agent pipeline that turns a rough idea into a structured, production-ready AI prompt. Runs entirely in the browser from a single HTML file — no Python, no server, no install required. The agents run in sequence: Intake diagnoses what is present or missing, Build constructs the finished five-part prompt, and Quality scores the result and explains what makes it work.

Repo location

agents/prompt-builder/index.html
Module version: agents/prompt-builder/agents.js

Runtime type

Standalone browser tool
Open index.html directly in Chrome or Firefox
No server or local port required

API key requirement

ANTHROPIC_API_KEY — entered in the browser UI
Stored in session memory only
Never written to disk or storage

Dependencies

None. No pip install. No npm.
Uses fetch to call the Anthropic API directly.
Requires an internet connection.

How to open
Kelex — any method 
# Windows Explorer — double-click to open in default browser
agents\prompt-builder\index.html

# Chrome from PowerShell
start chrome agents\prompt-builder\index.html
User flow

1. Open index.html in Chrome or Firefox
2. Enter your Anthropic API key — the field collapses after entry
3. Paste a rough prompt or idea into the text area
4. Click Build Prompt
5. If Agent 1 needs more information, answer the clarifying questions and click Continue
6. Review the finished five-part prompt in the output panel
7. Click Copy to copy the prompt to clipboard
8. Review the confidence score and "Why this works" explanation below the prompt

The three sub-agents
Agent 1 — Intake

Reads the raw input and classifies each of four framework parts (Role, Context, Task, Format) as present, partial, or missing. Passes a diagnosis forward or returns focused clarifying questions if there is not enough signal.

Agent 2 — Build

Takes the diagnosis and constructs the finished five-part prompt: Role, Context, Task, Format, Constraints. Applies consistent style rules — active voice, no dashes, no marketing language, concrete and direct.

Agent 3 — Quality

Scores the finished prompt 0.0 to 1.0 based on how much came from explicit input versus assumptions. Writes a short explanation of what makes it effective and flags any assumptions the user should review.

Credentials & Settings

Where secrets live — and where they must never appear.

⚠️ This page never stores or collects real credentials.

No API keys, tokens, or passwords belong in any static HTML file, JavaScript file, or anywhere in this repo. All secrets live in local .env files on your machine (never committed to git) or in secure server-side environment variables.

Local agents — .env file

All agents in Xannith/ai-agents load credentials from a .env file in the repo root. A template is included at .env.example.

Copy the template and fill in your real values:

Kelex — PowerShell 
# From the ai-agents repo root
Copy-Item .env.example .env
# Then open .env in VS Code and add your keys
code .env

The .env file is already listed in .gitignore. Never commit it.

Known required variables (from .env.example)

ANTHROPIC_API_KEY All 4 agents, Pipeline Runner, Pipeline GUI Required for live runs. Get from console.anthropic.com
OPENAI_API_KEY OpenAI-based agents (if added) Not used by current agents — placeholder for future use

This dashboard's login password

The dashboard password is set directly in login.html as a plain JavaScript variable. It is visible to anyone who views page source.

To change it: open /login.html in an editor and update the DASHBOARD_PASSWORD variable near the bottom of the file. Then commit and deploy.

For real protection, replace this static login with one of the options below.

login.html — find and change this line 
// TODO: Change this to a password of your choosing.
var DASHBOARD_PASSWORD = 'changeme';

Launch Instructions

Two machines are involved. Claude Code runs on Brainiac (Linux). You test and run agents on Kelex (Windows). Changes flow through GitHub.

Two-machine workflow

BRAINIAC (this machine)

Claude Code edits agent files here.
Path: /home/jbechtel/ai-agents
Commits and pushes to GitHub.

KELEX (Windows workstation)

You run and test agents here.
Path: C:\Projects\ai-agents
Pull from GitHub to get latest changes.

Sync order: Brainiac pushes → GitHub → Kelex pulls

  1. 1
    Get the latest code on Kelex

    After Claude Code makes changes on Brainiac and pushes to GitHub, pull them on Kelex:

    Kelex — PowerShell 
    cd C:\Projects\ai-agents
git pull

    If the repo isn't cloned yet on Kelex, clone it first:

    Kelex — PowerShell (first-time setup only) 
    cd C:\Projects
git clone https://github.com/Xannith/ai-agents.git
cd ai-agents
  2. 2
    Create a Python virtual environment (first-time only)

    Do this once on Kelex. Isolates dependencies from your system Python.

    Kelex — PowerShell 
    cd C:\Projects\ai-agents
python -m venv .venv
  3. 3
    Activate the virtual environment
    Kelex — PowerShell 
    .venv\Scripts\Activate.ps1

    Your prompt should show (.venv) when active. If PowerShell blocks the script, run this once first:

    Kelex — PowerShell (one-time fix) 
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
  4. 4
    Install dependencies

    No root-level requirements.txt exists — install from the specific agent folders:

    Kelex — PowerShell 
    python -m pip install --upgrade pip

# Core agent dependencies (shared by all 4 CLI agents + Pipeline Runner)
